# Task v0.1-01: Single LIF neuron

You write this one yourself. The tests in `tests/test_lif_single.py` define what "correct" means.

## Concept

A leaky integrate-and-fire neuron has a membrane potential `v` that:

1. leaks back toward a resting value `v_rest`,
2. is pushed up by an input current,
3. when it reaches a threshold `v_th`, emits a spike and is reset to `v_reset`.

Continuous-time equation:

```
tau_m * dv/dt = -(v - v_rest) + r_m * i_ext(t)
```

Discretize with forward Euler (`dt` is the time step):

```
v[t+1] = v[t] + dt / tau_m * ( -(v[t] - v_rest) + r_m * i_ext[t] )
```

Then check for a spike: if `v >= v_th`, record the time and set `v = v_reset`.

Units (so everything is consistent): time in **ms**, potential in **mV**, current in **nA**, resistance in **MOhm** (nA x MOhm = mV).

## Required interface

File: `src/flybot/lif.py`

```python
def simulate_lif(
    i_ext,            # 1-D array, input current in nA, one value per time step
    dt,               # time step in ms
    *,
    tau_m=20.0,       # ms
    v_rest=-70.0,     # mV
    v_reset=-75.0,    # mV
    v_th=-50.0,       # mV
    r_m=10.0,         # MOhm
    t_ref=0.0,        # ms, refractory period (0 = none)
):
    """Return (v, spike_times).

    v: array, same length as i_ext, membrane potential at each step
    spike_times: array of spike times in ms
    """
```

Details to decide and document in your docstring:

- What is `v` at step 0? (The tests assume `v_rest`.)
- At which time do you record a spike: the step where `v` crossed threshold? Be consistent.
- If `v` is reset on a spike, should the stored `v` for that step be the pre-reset peak or `v_reset`? Either is fine, but say which.

Refractory period (`t_ref`) is optional for the first tests: with `t_ref=0.0` there must be no refractory behaviour. Implement it when you are ready; there is a test for it that checks that two spikes are never closer than `t_ref`.

## Steps

1. Get the environment working: `pip install -e ".[dev]"` then `pytest` (all tests should be skipped at first).
2. Write `simulate_lif` with a plain Python loop first. Do not vectorize yet; a single neuron has a time dependence that needs a loop.
3. Run the tests and fix failures. Read the failure messages: they describe the property that was violated.
4. Write `experiments/v0_1_single_neuron.py` that plots `v(t)` and spike times for input currents of 1, 2, 3 and 4 nA.
5. Think about these questions and put your answers in `docs/devlog/`:
   - Why does 1 nA never produce a spike, while 3 nA does? Compute the threshold current analytically.
   - Halve `dt`. What changes in the output? Why?
   - What happens with a very large `dt` (for example, equal to `tau_m`)?

## Done when

- Your dev log entry answers the three questions.

## Hints (only if stuck)

- The rheobase (minimal current that makes the neuron spike) follows from the steady state of the equation with `dv/dt = 0`.
- For a constant current above rheobase, the interval between spikes has a closed form. Deriving it is a good exercise; the tests use it.
