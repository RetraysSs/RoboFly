# Task v0.2-01: LIF network state and vectorised update

- **Version:** v0.2
- **Files:** `src/flybot/network.py`, `tests/test_network_neurons.py`
- **Status:** open

## Objective

Implement a `LIFNetwork` class that holds the state of N leaky integrate-and-fire neurons and advances all of them at once. In this task the neurons are independent (no synapses yet); the constructor already takes the weight matrix so that task v0.2-02 does not change the interface.

## Background

**Vectorisation.** In v0.1 one neuron was simulated with a Python loop over time. For N neurons the loop over neurons is replaced by array operations: `v` becomes an array of shape `(n,)` and one expression updates all neurons. NumPy executes this in compiled code, which is orders of magnitude faster than a Python loop over neurons.

**Boolean masks.** A comparison such as `v >= v_th` returns an array of `True`/`False` values (one per neuron). A mask can select elements for assignment (`v[mask] = v_reset`) and `np.flatnonzero(mask)` returns the indices where it is `True`.

**State in a class.** The simulator is called repeatedly on short windows later in the project (the robot control loop), so the state (potentials, refractory counters, elapsed steps) lives in an object between calls. Python's `__init__` plays the role of a constructor, `self` is `this`, and attributes are created by assigning to `self.<name>`.

The neuron model, units and conventions are the same as in v0.1 (`docs/devlog/2026-11-09-single-lif-neuron.md`).

## Interface

File: `src/flybot/network.py`

```python
class LIFNetwork:
    def __init__(self, weights, dt, *,
                 tau_m=20.0, v_rest=-70.0, v_reset=-75.0,
                 v_th=-50.0, r_m=10.0, t_ref=0.0):
        """weights: (n, n) array. Unused in this task but stored as `self.weights`."""

    # attributes
    #   n        number of neurons
    #   v        np.ndarray, shape (n,), membrane potentials (mV), start at v_rest
    #   weights  the weight matrix
    #   n_steps  number of steps performed so far
    #   t        property: elapsed time in ms, n_steps * dt

    def step(self, i_ext=0.0, jump_ext=0.0):
        """Advance by one time step. i_ext: scalar or shape (n,), in nA.
        Return a boolean array of shape (n,): which neurons spiked."""

    def run(self, i_ext, jump_ext=None, on_step=None):
        """Advance by len(i_ext) steps and return (spike_times, spike_ids)."""
```

`jump_ext` and `on_step` are used in task v0.2-02. In this task the signatures may accept them without using them.

Behaviour required:

- `run(i_ext)` performs `len(i_ext)` updates. `i_ext` has shape `(T,)` (the same current for every neuron) or `(T, n)` (one current per neuron and step).
- `run` returns two 1-D arrays of equal length: spike times in ms and neuron indices, sorted by time.
- Spike time convention as in v0.1: the time at which the new potential reached the threshold, `n_steps_after_update * dt`.
- State persists between calls: `run(a)` followed by `run(b)` equals `run(concatenate(a, b))`, and spike times keep counting from the elapsed time.
- Refractory behaviour as in v0.1: after a spike the neuron is held at `v_reset` for `round(t_ref / dt)` steps and cannot spike.
- A network of independent neurons reproduces `simulate_lif` from v0.1 neuron by neuron.

## Implementation notes

- Keep the update expression in the same operation order as in `lif.py` (`dt / tau_m * (...)`). Floating-point results then match v0.1 exactly, which the comparison tests rely on.
- The refractory counter is an integer array of shape `(n,)`. A boolean mask of the neurons currently in the refractory state avoids a loop over neurons.
- `run` may still contain a Python loop over time steps; the loop over neurons is what must disappear.
- One extra sample is needed when comparing with `simulate_lif`: it performs `len(i_ext) - 1` updates, `run` performs `len(i_ext)`. The tests pad one sample.
