# Task v0.2-02: Synapses, mutable weights and a step hook

- **Version:** v0.2
- **Files:** `src/flybot/network.py`, `tests/test_network_synapses.py`
- **Status:** open
- **Depends on:** v0.2-01

## Objective

Connect the neurons: a spike of neuron `j` changes the membrane potential of neuron `i` through a weight matrix. The weights must remain ordinary, changeable data of the network, so that learning rules can modify them during a simulation later in the project (v2.0).

## Background

**Delta synapses.** The simplest synapse model: when neuron `j` spikes, the potential of every postsynaptic neuron `i` jumps by `weights[i, j]` mV. Positive weights are excitatory, negative weights are inhibitory. Rows are postsynaptic neurons, columns are presynaptic neurons.

**Total jump as a matrix-vector product.** Let `spiked` be a vector of 0 and 1 (1 for the neurons that spiked in this step). Then `weights @ spiked` is the vector of total jumps for all neurons.

**Sparse matrices.** The FlyWire connectome has about 139,000 neurons. A dense 139,000 x 139,000 matrix of 64-bit floats would need roughly 155 GB, while a neuron is connected to only a small fraction of the others. `scipy.sparse` matrices (for example `csr_matrix`) store only the non-zero entries and support the same `weights @ vector` product. The network must work with both dense NumPy arrays and sparse matrices.

**Timing.** The jump is added at the end of the step in which the presynaptic spike occurred. The postsynaptic neuron can therefore spike at the earliest one step later. This is intended to correspond to Brian2 with zero synaptic delay; task v0.2-04 verifies whether it does.

## Required behaviour

- `weights[i, j]`: jump (mV) of neuron `i` when neuron `j` spikes.
- Sequence inside `step`: update all non-refractory neurons, detect spikes, reset the spiking neurons, then add the jumps caused by the spikes of this step.
- A neuron whose refractory counter is above zero after the update (including a neuron that has just spiked, when `t_ref > 0`) does not receive jumps.
- `jump_ext`: extra voltage jumps in mV added in the same way as synaptic jumps. In `step` it is a scalar or an array of shape `(n,)`; in `run` it is an array of shape `(T, n)`. This is the input channel for Poisson spike trains (task v0.2-03).
- `weights` is a public attribute that is read at every step and is **not copied** at construction. Changing one entry in place (`net.weights[1, 0] = 25.0`) or assigning a new matrix (`net.weights = new`) must take effect immediately.
- `run(..., on_step=hook)`: after every step the network calls `hook(net, k, spiked)`, where `k` is the step index within this call (starting at 0) and `spiked` is the boolean mask of the step. The hook may modify `net.weights`. The default is `None`.

## Implementation notes

- `weights @ spiked.astype(float)` works for dense and sparse weights.
- Dense and sparse products add the same numbers in a different order, which can change the last bits of floating-point results. The tests use weights that are multiples of 0.5, so both give identical results; this is not guaranteed for general weights.
- The hook is intentionally minimal. It is the place where a plasticity rule (for example a reward-modulated weight update) is attached in later versions.
