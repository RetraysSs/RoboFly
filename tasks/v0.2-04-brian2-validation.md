# Task v0.2-04: Validation against Brian2

- **Version:** v0.2
- **Files:** `experiments/v0_2_brian2_validation.py`
- **Status:** open
- **Depends on:** v0.2-02, v0.2-03
- **Setup:** `pip install -e ".[ref]"` (installs Brian2)

## Objective

Show that the custom simulator produces the same activity as an established simulator on the same network. This is the evidence that the simulator can be trusted when it runs the real connectome in v0.3.

## Background

[Brian2](https://brian2.readthedocs.io/) is a widely used spiking-network simulator. The relevant tutorial parts are *Neurons* and *Synapses*, and the documentation of `NeuronGroup`, `Synapses`, `SpikeMonitor` and `defaultclock`.

An exact spike-for-spike match is not guaranteed, because two implementations can differ in details: the order of operations inside a time step, whether the threshold test uses `>` or `>=`, how a refractory period is counted, and floating-point rounding. In a network, a difference of one time step in one spike can change later spikes. The validation therefore proceeds in stages and ends with a stated tolerance instead of an exact match.

## Method

Use identical parameters in both simulators: `dt`, `tau_m`, `v_rest`, `v_reset`, `v_th`, `r_m`, weights, and the same inputs. Avoid random inputs in the comparison: use constant currents, or generate the Poisson jump arrays once and feed the same arrays to both simulators.

Stages:

1. **One neuron.** Constant current. Compare the spike times with `simulate_lif` and with `LIFNetwork`. Differences here point to a convention difference (integration method, threshold test, time of the spike).
2. **Two neurons, one synapse.** Compare the time difference between the presynaptic and the postsynaptic spike. This checks the synapse timing rule.
3. **Random network** (for example N = 100, 10% connectivity, mixed excitatory and inhibitory weights, constant currents). Compare per-neuron spike counts and the spike times.

Brian2 notes (check the documentation for the exact syntax):

- Set the integration method to Euler (`method='euler'`) and the clock to the same `dt`, so both simulators use the same scheme. The Brian2 tutorial examples use `method='exact'`, which solves the linear equation exactly instead of in time steps. A third run with `'exact'` serves as a reference for the discretisation error of both Euler implementations (compare with the `dt` analysis in the v0.1 dev log, where the analytic first spike time was 21.972 ms).
- Brian2 variables may be dimensionless (the tutorial uses `v : 1`). Interpreting `v` as a number in mV avoids unit conversions; time constants and the clock still carry `ms`.
- **Refractoriness.** In Brian2, `refractory=...` on the `NeuronGroup` only prevents spikes. To also hold the potential constant during the refractory period, the membrane equation needs the flag `(unless refractory)`. The simulator in this project holds `v` at `v_reset` during the refractory period, which corresponds to the version with the flag. Without it the potential keeps charging in Brian2 and behaves differently.
- Possible sources of small differences to check: the exact number of steps the refractory period lasts (a period of `t_ref` is counted in whole steps), whether synaptic jumps reach a refractory neuron, and the order of the update, threshold test and synaptic jump inside a time step.
- The membrane equation is the same as in this project: `dv/dt = (-(v - v_rest) + r_m * I) / tau_m`.
- Synapses with `on_pre='v_post += w'` and no delay are the counterpart of the jump rule in task v0.2-02. Check in the documentation when exactly during the time step the jump is applied, and compare with the rule used here.
- Brian2 attaches units to quantities. Strip them with a division (`spike_times / ms`) before comparing arrays.
- Weights can be transferred from a SciPy sparse matrix by connecting the non-zero entries (`i`, `j` indices) and assigning their values.

## Deliverables

1. `experiments/v0_2_brian2_validation.py` running the three stages and printing a comparison table.
2. A dev log entry with:
   - the table (per-stage maximum difference in spike count and in spike time),
   - the tolerance chosen and why,
   - every difference found between the simulators and what caused it.

## Acceptance criteria

- Stage 1 and 2 agree within one time step `dt`, or each difference is explained and documented.
- In stage 3 the per-neuron spike counts agree within a stated tolerance.
- The script reproduces the table from the repository.
